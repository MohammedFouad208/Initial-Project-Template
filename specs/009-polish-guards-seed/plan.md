# Implementation Plan: Polish, Guards & Seed Data

**Branch**: `009-polish-guards-seed` | **Date**: 2026-04-12 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/009-polish-guards-seed/spec.md`

## Summary

Phase 9 hardens the existing ASP.NET Core Admin Template for production readiness. The previous eight phases produced a fully functional application; this phase closes the remaining gaps: demo seed data for all three access tiers, styled 403/404 error pages, a global toast notification system, jQuery Validate + Bootstrap 5 real-time form validation, SMTP configuration, a README, and a final design system compliance audit resolving all found `@Html.Partial()` and inline-style violations. No new entities or API surfaces are introduced — this is entirely an enhancement and hardening pass over existing files.

**Target Platform**: Windows Server / IIS or Kestrel — any ASP.NET Core 8 host  
**Project Type**: ASP.NET Core MVC web application (admin template)  
**Performance Goals**: No degradation from existing baselines; toast renders within one animation frame  
**Constraints**: No new NuGet packages; no new CDN scripts; all changes use existing dependency set  
**Scale/Scope**: Single-tenant admin template; 3 seed roles, ~5 views modified, 2 JS functions added

### Implementation Guide (quickstart)

**For the developer implementing this phase, in order:**

#### Step 1 — Fix `_Layout.cshtml` (foundational; all other steps depend on correct layout)

Replace `@Html.Partial("_Sidebar")` → `<partial name="_Sidebar" />`.  
Replace `@Html.Partial("_Topnav")` → `<partial name="_Topnav" />`.  
Add toast container div immediately before `</body>`.  
Add TempData toast script block after `site.js` script tag.

#### Step 2 — Add `AppToast.show()` to `site.js`

Add `AppToast` namespace object at the end of `site.js`:

```javascript
var AppToast = (function () {
    function show(message, type) {
        type = type || "info";
        var colors = {
            success: "var(--success)",
            danger:  "var(--danger)",
            warning: "var(--warning)",
            info:    "var(--info)"
        };
        var accent = colors[type] || colors.info;

        var id  = "toast-" + Date.now();
        var el  = document.createElement("div");
        el.id   = id;
        el.className = "toast align-items-center text-bg-dark border-0 shadow";
        el.setAttribute("role", "alert");
        el.setAttribute("aria-live", "assertive");
        el.setAttribute("aria-atomic", "true");
        el.style.borderInlineStart = "4px solid " + accent;

        el.innerHTML = [
            '<div class="d-flex">',
            '  <div class="toast-body">' + message + '</div>',
            '  <button type="button" class="btn-close btn-close-white me-2 m-auto"',
            '    data-bs-dismiss="toast" aria-label="Close"></button>',
            '</div>'
        ].join("");

        var container = document.getElementById("toast-container");
        if (container) { container.appendChild(el); }

        var toast = bootstrap.Toast.getOrCreateInstance(el, { delay: 4000 });
        el.addEventListener("hidden.bs.toast", function () { el.remove(); });
        toast.show();
    }
    return { show: show };
}());
```

#### Step 3 — Update `_ValidationScriptsPartial.cshtml`

Add Bootstrap 5 adapter after existing script references. See [research.md](research.md#decision-2) for exact code.

#### Step 4 — Verify `@section Scripts` in all form views

Ensure `Create.cshtml` and `Edit.cshtml` for Users, Roles, and RolePermissions all end with:
```cshtml
@section Scripts {
    <partial name="_ValidationScriptsPartial" />
}
```

#### Step 5 — Redesign `Error403.cshtml`

Replace the current generic card with:
- Icon in a `<div class="error-icon-circle danger-circle">` (defined in `site.css`)
- `<i class="fa-solid fa-lock"></i>` inside the circle
- Back button as `.btn.btn-outline-secondary`
- Page wrapped in `.page-header` pattern

Add CSS in `site.css`:
```css
.error-icon-circle {
    width: 5rem;
    height: 5rem;
    border-radius: 50%;
    display: flex;
    align-items: center;
    justify-content: center;
    margin: 0 auto 1.5rem;
    font-size: 2rem;
}
.error-icon-circle.danger-circle  { background: var(--danger-light,  #fee2e2); color: var(--danger);  }
.error-icon-circle.warning-circle { background: var(--warning-light, #fef3c7); color: var(--warning); }
.error-icon-circle.info-circle    { background: var(--info-light,    #e0f2fe); color: var(--info);    }
```

#### Step 6 — Create `Error404.cshtml` and `ErrorController.Error404()`

Add `ErrorController.cs` with a simple `[AllowAnonymous]` `Error404` action.  
Add `Program.cs` middleware: `app.UseStatusCodePagesWithRedirects("/Error/404");` (before `app.UseRouting()`).  
Create `Views/Error/NotFound.cshtml` modelled on the redesigned 403 page (use `.warning-circle` + `fa-solid fa-map-location-dot` or `fa-solid fa-circle-question`).

#### Step 7 — Fix inline styles in breadcrumbs

Add `.breadcrumb-link { color: var(--primary); text-decoration: none; }` to `site.css`.  
Replace all `style="color:var(--primary)"` occurrences on breadcrumb anchors with `class="breadcrumb-link"`.  
Affected views: `Users/Create.cshtml`, `Users/Edit.cshtml`, `Roles/Create.cshtml`, `Roles/Edit.cshtml` (check all views for same pattern).

#### Step 8 — Gate `RolePermissions` sidebar link

In `_Sidebar.cshtml`, add:
```csharp
var canAssignPermissions = sidebarUserId != Guid.Empty
    && await PermissionService.UserHasPermissionAsync(sidebarUserId, "Role", "AssignPermissions");
```
Apply `@(canAssignPermissions ? "" : "d-none")` to the Role Permissions nav link.

#### Step 9 — Extend `DataSeeder.cs`

Add `SeedDemoRolesAsync()` method after existing SuperAdmin seed logic:
1. Create `Admin` role if not exists.
2. Seed Admin role permissions: iterate all permission objects from `IPermissionProvider`; for each, add Browse, Create, Update (filter by whitelist; skip if function not in object's available functions).
3. Create `admin@admintemplate.local` user from config; assign to Admin role.
4. Create `Viewer` role if not exists.
5. Seed Viewer role permissions: Browse only.
6. Create `viewer@admintemplate.local` user from config; assign to Viewer role.
7. Add `Seed:AdminEmail`, `Seed:AdminPassword`, `Seed:ViewerEmail`, `Seed:ViewerPassword` keys to `appsettings.json`.

#### Step 10 — `appsettings.json` SMTP section + seed keys

Add `Smtp` section and new `Seed` keys as documented in [data-model.md](data-model.md).

#### Step 11 — Write `README.md`

Minimum sections:
1. **Prerequisites** — .NET 8 SDK, SQL Server, Visual Studio / VS Code
2. **Setup** — clone; update `ConnectionStrings:DefaultConnection`
3. **Database** — Open PM Console → `Update-Database` (default project: Infrastructure)
4. **Seed Data** — Auto-runs on first app start; default credentials table
5. **Run** — F5 or `dotnet run`
6. **Default Credentials** — table of all 3 seed users
7. **Configuration** — notes on SMTP, lockout, moving credentials to user secrets

#### Step 12 — Final Design System Audit

Walk every `.cshtml` file and verify:
- [ ] No hardcoded hex/named colors outside `site.css` token definitions
- [ ] No `margin-left`, `padding-right`, `left:`, `right:` in shared CSS
- [ ] No `@Html.Partial()` calls
- [ ] All breadcrumb links use `.breadcrumb-link` class
- [ ] Error pages use icon-in-circle pattern
- [ ] Toast container present in `_Layout.cshtml`
- [ ] All forms include `@section Scripts { <partial name="_ValidationScriptsPartial" /> }`
